# 架构与保证边界

`server.ts` 提供标准 stdio MCP、阶段资源和提示模板。`registry.ts` 集中维护 Zod schema、用途、读写属性、执行策略和处理器；默认直接工具与 eda_invoke 共用校验。`toolkit.ts` 组织有边界的设计动作，`eda.ts` 负责实际 API 与单位适配，`geometry.ts` 使用 Flatten 的多边形、距离与空间索引。

`runtime.ts` 在每次 API 执行前核验窗口、工程、文档 UUID 和文档类型；每个窗口在单进程内排队，共用 EASYEDA_STATE_DIR 的进程使用文件系统锁互斥。不同进程争用时返回 WINDOW_BUSY；崩溃残留锁不会自动抢占。所有客户端必须使用同一个绝对状态目录。用户在 EDA 界面手动切页仍可能打断多步操作，后续请求会被目标门阻止。

写入前保存文档源备份，每个 Runtime 首次写入工程时另存 epro2；持久化 operationId 防止重放。超时或部分失败后读回源文件并返回实际已知变更、备份和恢复证据。保存成功不等于修改成功；创建、移动、路径覆盖、原生 DRC 与连通图分别报告。

路径检查使用真实焊盘形状、旋转、已有铜线、通孔过孔、板框与已知禁布多边形。`polygon.ts` 解析真实线段和圆弧，区分固定实心 Fill 的孔洞与分离岛屿，拼接 Line/Arc/Polyline 板框；适配器读取明确 NO_WIRES 区域。未标定的 Poured 填充、内层、铜弧走线和特殊焊盘仍标记 unknown。原生 DRC 检查当前设计规则；自定义 clearance 不能替代制造规则。

`pcb-primitives.ts` 提供原始属性、编辑 revision 和能力读取；`pcb-editing.ts` 为焊盘、固定铜、覆铜和已有板框提供独立的受校验写入。路由所需完整几何不可用时，不因此隐藏可用编辑能力。默认直接暴露所有启用工具的 schema；compact 模式只改变展示，不能绕过策略。

修改后核对请求及已观察的未变字段。官方板框修改可能返回旧 ID：仅在旧对象消失、出现唯一新对象且所有已观察属性符合预期时接受新 ID，并记录编号变化。不会认领原先就存在的相似对象。替换板框先创建并读回，再删除显式列出的旧对象；不是原子事务。

EDA 会合并重合线段，返回 ID 不一定长期存在，因此路径验证还比较每段同层同网铜线的连续覆盖、线宽与过孔尺寸。恢复工具只接受记录中的明确 ID；图元被合并、删除或后续改动时，不提供源文件全量覆盖回退。回退不构成事务原子性保证。

保存重开时，PCB 对比保留对象 ID、网络、层与拓扑的精确比较，数值容差为 0.00001（坐标单位 mm），容纳实测约 0.000001 mm 的持久化舍入；仍输出最大变化量与差异。原理图比较电气哈希。该容差不放宽布线净距约束。

0.2.0 同时比较原始编辑对象，避免路由模型中 unknown 的 Pour 被漏检。原始属性数值容差 0.0005 mil；单位未标定的 Poured 数据只做精确持久化比较。明确无钻孔焊盘的孔旋转/孔偏移不参与几何比较，并在证据列出不适用字段；有钻孔时仍严格检查。API 的 `hole:null` 修改存在意外创建默认钻孔的行为，因此移除已有孔被提前拒绝，无孔的冗余 null 不传给原生修改接口。

截图校验同时提供像素信息与原生 MCP image；像素非空仅排除空图，必须由模型视觉检查。字体原生单位未标定，因此公开整理工具仅调整坐标、对齐、旋转或恢复默认字体。
